---
title: "monte sync, push"
description: "The two directions of the results bucket"
---

```bash
monte sync [experiment...] [--bucket B] [--key-file PATH] [--json]
monte push <experiment> [--run R] [--bucket B] [--key-file PATH] [--json]
```

`sync` and `push` are the two directions of the durable tier, the cloud results bucket that outlives any box.

`sync` pulls the bucket into a local Mirror, and defaults to every Experiment in it. A Mirror is a read-only local copy of the results, so you can read Ledger state with no box up. Weights never enter it. The durable copy wins on disagreement, `sync` never deletes a local-only file, and it skips weight objects, because weights live on Hugging Face.

`push` uploads one Experiment's local results tree, new and changed files only. `--run` narrows it to a single Run plus the Experiment's own files. `push` deletes nothing remote, so retention stays a separate deliberate act. It also refuses a weight file.

Both resolve a GCS service-account key: `--key-file`, then `MONTE_GCS_KEY_FILE`, then the 1Password document `MONTE_GCS_KEY_OP` names, fetched in memory. Without one, `E_STORAGE`.
