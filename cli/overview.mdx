The `monte` CLI is the only write path into the platform. This page covers the conventions commands share, where they run, and their exit codes. [Commands](/cli/commands) documents the commands themselves.

## Conventions

- **Command Forms:** `monte eval <experiment>` means `monte eval run <experiment>`, and the same shorthand applies to `train`. Options may appear before the experiment name. The `experiment`, `env`, `dataset`, and `box` groups always require an explicit subcommand.

- **Confirmation:** `eval run` and `train run` print a run plan and ask for confirmation. Pass `--yes` to skip the prompt or `--dry-run` to print the plan without launching. A non-interactive launch without `--yes` refuses with `E_CONFIRM`.

  For promotion, `monte promote` requires `--confirm <experiment-name>` rather than a y/n prompt.

- **Names:** A run is `<experiment>/<run>`, where `<run>` is a ULID or an `eval@N` or `train@N` alias. An alias must resolve to one succeeded run; Monte never chooses between matches by ledger order.

  A checkpoint is `<run>/<step>`. The run is always a ULID, and the step is counted from the base model. Checkpoint names do not accept aliases because more than one branch can contain the same step.

- **JSON Output:** Where supported, `--json` writes machine-readable output to stdout and sends the human plan summary to stderr. `status --json` does not include the checkpoint list shown in the human view.

## Where a Command Runs

Three groups, and a command run from the wrong group is the most common source of a refusal.

| Group | Runs From | Commands |
| --- | --- | --- |
| Anywhere | a tool install or a checkout | `experiment`, `status`, `logs`, `show`, `env`, `dataset`, `config` |
| Laptop | a clean git checkout pushed to origin | `--remote` on `eval` and `train`, `box` |
| GPU | the GPU box holding the checkpoint | real `eval` and `train`, `--push`, `promote`, `weights`, `envelope` |

`--remote` reads the git state of the checkout it runs from, so a `uv tool` install refuses it (`E_REMOTE`). `promote` copies weights off disk, so it runs where they live.

The first row has a precondition the others do not. `env add`, `env list --available`, and `env install` all read or write the NeMo Gym checkout, so they need a machine that holds the Gym stack. Installing a mock-only environment is the exception, because it has nothing to register.

## Exit Codes

| Exit | Result | Returned when |
|---|---|---|
| 0 | success | Command completed. |
| 1 | aborted | Confirmation was interrupted or stdout closed. |
| 2 | usage | Invalid CLI usage, such as a bad flag or missing argument. |
| 3 | `E_REFUSAL` | A platform rule refused the command. |
| 3 | `E_NO_BASELINE` | Training has no matching cohort baseline. |
| 4 | `E_FROZEN_FIELD` | A launch would change a frozen experiment field. |
| 5 | `E_NOT_COMPARABLE` | The run's comparability configuration does not match its cohort. |
| 6 | `E_PREFLIGHT` | A required host or evaluation check failed. |
| 7 | `E_CONFIRM` | Confirmation was declined, missing, or did not match. |
| 8 | `E_MEASUREMENT_EXISTS` | `experiment init` used an existing name. |
| 9 | `E_NOT_FOUND` | The named object was absent or could not be read. |
| 10 | `E_NOT_RUNNING` | `stop` targeted a run that is not running. |
| 11 | `E_CORRUPT_STATE` | Ledger or frozen input state failed integrity checks. |
| 12 | `E_SERVING` | The serving stack could not produce a measurement. |
| 13 | `E_VERIFICATION` | A completed run or checkpoint failed verification. |
| 14 | `E_STORAGE` | Remote storage could not be reached. |
| 15 | `E_BOX` | Box allocation or operation failed. |
| 16 | `E_REMOTE` | Remote submission or shipping failed. |
| 17 | `E_ENVELOPE` | The action falls outside the active Envelope. |
