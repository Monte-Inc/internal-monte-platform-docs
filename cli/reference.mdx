What the CLI resolves before it runs anything, the variables that set it, and the codes it exits with.

## monte config

```bash
monte config [--json]
```

Prints the resolved configuration: the data root and its source, the GPU check command, mock seconds, the base-model pin, the installed Environments, the resolvable Recipe names with their search path, and the schema version.

## Environment variables

Paths and execution:

| Variable | Meaning | Default |
|---|---|---|
| `MONTE_ROOT` | durable data root: Experiments, Ledger, Splits, Datasets | `~/monte-post-training/monte-platform` |
| `MONTE_LOCAL` | disposable box-local root: venvs, caches, scratch | `~/monte` |
| `MONTE_RECIPES` | a directory of Recipes, searched before the packaged ones | unset |
| `MONTE_GPU_CHECK_CMD` | command for the foreign-process GPU check in a real preflight. Empty disables that check | auto |
| `MONTE_MOCK_SECONDS` | how long a mock run lasts, in seconds | `30` |
| `MONTE_GPU_MEM_UTIL` | fraction of GPU memory the eval server can claim | `0.9` |
| `MONTE_DOCKER` | docker command override, for example `sudo docker` | `docker` |

Credentials. Each one resolves from a direct value first, then from 1Password. Monte fetches a 1Password secret in memory, so nothing lands on disk.

| Variable | Meaning | Default |
|---|---|---|
| `MONTE_LAMBDA_KEY` | Lambda API key for `box` and `--remote` | unset |
| `MONTE_LAMBDA_KEY_OP` | 1Password item holding it instead | unset |
| `MONTE_GCS_KEY_FILE` | GCS service-account JSON path for `sync` and `push` | unset |
| `MONTE_GCS_KEY_OP` | 1Password document holding it instead | unset |
| `MONTE_GCS_BOX_KEY_FILE` | the key written to a box, when it differs from yours | unset |
| `MONTE_GCS_BOX_KEY_OP` | 1Password document holding that one | `GCS SA key - monte-box (rw monte-platform-results)` |
| `HF_TOKEN` | Hugging Face token: a real train pushes Checkpoints there, `env add --server` freezes with it, and `dataset add --from-hf` reads gated repos with it | unset |
| `MONTE_HF_TOKEN_OP` | 1Password item holding it instead | unset |
| `MONTE_HF_ORG` | Hugging Face org the weights repos live under | `monte-inc` |
| `MONTE_OP_ACCOUNT` | 1Password account for every `op` lookup above | unset |
| `MONTE_OP_VAULT` | 1Password vault for every `op` lookup above | unset |

Box provisioning:

| Variable | Meaning | Default |
|---|---|---|
| `MONTE_SSH_KEY_NAME` | account SSH key name, needed when the account has several | unset |
| `MONTE_NFS_NAME` | the NFS a warm box attaches | `monte-post-training` |
| `MONTE_STATE_DIR` | directory holding the box identity file | `~/.monte` |

## Exit codes

| Code | Name | Fires when |
|---|---|---|
| 0 | success | |
| 1 | aborted | Ctrl+C at the confirm prompt, or a broken pipe |
| 2 | usage | Click usage errors: a bad flag, a missing argument, a missing `--recipe` or `--source` |
| 3 | `E_REFUSAL` | a refusal with no more specific code: an unstated starting point, a crossed Recipe and source, a continuation that changes its source, two flags naming one target |
| 3 | `E_NO_BASELINE` | train without a matching-Cohort Baseline |
| 4 | `E_FROZEN_FIELD` | a launch would change a frozen Experiment field |
| 5 | `E_NOT_COMPARABLE` | comparability config does not match the Cohort |
| 6 | `E_PREFLIGHT` | preflight failed: the lock, fingerprint drift, the free-space minimum, a foreign GPU process, a test eval on a Cohort with no `test@0` baseline, or a final-claim selection whose candidates are not all pairable |
| 7 | `E_CONFIRM` | declined prompt, non-TTY without `--yes`, or a promote `--confirm` mismatch |
| 8 | `E_MEASUREMENT_EXISTS` | `experiment init` on a name that exists |
| 9 | `E_NOT_FOUND` | no such Experiment, Run, Environment, Dataset, or Checkpoint |
| 10 | `E_NOT_RUNNING` | stop on a Run that is not running. Exception: an abandoned Run with an orphaned container is still stoppable |
| 11 | `E_CORRUPT_STATE` | Ledger or pairing state is inconsistent |
| 12 | `E_SERVING` | the serving stack produced no measurement: no snapshot, vLLM down, Gym failed, or no rollouts |
| 13 | `E_VERIFICATION` | a finished Run failed its count or content check, or a promote checksum failed |
| 14 | `E_STORAGE` | the durable tier is unreachable: credentials, package, or path |
| 15 | `E_BOX` | monte could not get or operate a box: credentials, capacity, the Lambda API refusing, or a foreign instance |
| 16 | `E_REMOTE` | monte could not submit a remote Run: a dirty or unpushed tree, a box that cannot serve the Run, or a shipping step failing over SSH |

Codes 3 through 16 all print `CODE: cause (fix)` on stderr. Two names share code 3: `E_REFUSAL` is the base code, and `E_NO_BASELINE` carries the same exit value. Read the name on stderr, not the number, when you need to tell them apart.
