**Monte is the agent-native platform for post-training.**

AI agents can handle the individual tasks of post-training research well. They can change a training method, launch a run, or inspect an evaluation. They are much less reliable at managing the improvement process as a whole.

An agent may become overly convinced of an early diagnosis and keep working from it after the evidence shifts. It can chase a single metric and lose the broader goal. It may compare results produced under different conditions, repeat work it already did, or stick with an approach that stopped paying off. At each step it looks productive, while the process as a whole degrades.

Monte gives agents a consistent view of that process. It records the context behind each result and how the work changes over time, so an agent can revisit a decision and choose what to try next.

Monte fixes what has to be held still for a comparison to mean anything. Results are compared only against others produced the same way: the same starting model, the same frozen tasks, the same evaluation settings. Each such group carries its own baseline, and a comparison never crosses between groups. What Monte does not constrain is the training method or the research strategy.

## How It Works

Monte covers the post-training loop end to end. You define an Environment — its tasks, tools, state, and a grader — then evaluate a model against it, train with supervised fine-tuning or reinforcement learning, and evaluate again. The gap between those two numbers is the result.

A gap only supports a conclusion if both evaluations ran under identical conditions. Monte freezes those conditions when you define an experiment: the exact list of tasks, the decoding settings, how many attempts each task gets, and the grader that scores them. That consistency is strictly enforced, not just recorded: Monte refuses a training run when any of it has changed.

You pilot Monte from a CLI and a web console, both reading the same record. That is what lets people and agents collaborate across projects: an agent reads the conditions rather than inferring them, and anyone can see afterwards what it did and on what basis.

An Environment carries what you need to score a Task: the Tasks, their answers, and the grader. One Environment can carry several Experiments. `monte experiment init` creates an Experiment and fixes which Tasks you score and how you score them. An Experiment over a trainable Environment is one whose Tasks you can also train on. An Experiment over an eval-only Environment is a fixed reference any model can be scored against.

An Experiment starts from a base model, which can be any model. You score that base model twice before any training: on the `dev` Split, which sets the Baseline, and on the `test` Split, which anchors the final claim. Then you train and score each new Checkpoint against the Baseline. A Recipe states how a Run trains: the algorithm, the optimizer, the batch settings, and how it is distributed across GPUs. Each Run records the Recipe it ran and the Source it trained on, so the method behind a number is never lost. Monte writes the run plan, events, and training logs in the same shape for every Run. You can see from them which settings to change next.

The test Split is read twice: once on the base model before any training, and once on the Checkpoint Monte selects at the end. The final eval on the test Split is the number you report. `monte promote` copies a Checkpoint's weights out with its provenance, behind a confirmation you type in full. Every Run, score, and cost is recorded in that same shape. The driving agent reads that record, runs the loop, and decides what to try next.
